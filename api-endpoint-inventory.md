## Auth Boundary

`artifacts/api-server/src/routes/index.ts` mounts `healthRouter` first, then applies `requireAuth` before mounting portfolio, scraper, verdicts, advisor, alerts, AI-bot, and technical routers.

Therefore:

- `GET /api/healthz` is public.
- Every other endpoint in the table is behind `requireAuth`, including `/api/portfolio/scan`.
- The frontend raw helpers attach the current Supabase bearer token when a session exists.

### Sensitive endpoints for follow-up security review

These require particular attention in the later security task:

- `POST /api/portfolio/scan`: accepts a base64 screenshot and sends it to configured Qwen, Gemini fallback models, and optionally OpenRouter. It is authenticated through the router-level `requireAuth`, but undocumented in OpenAPI. The request body is `{ image: string, mimeType: string, mode: string }`. `mode` is interpreted as `order`, `nav`, `stock`, or `orders-list` behavior; the route does not use a typed schema for the outer body.
- `POST /api/portfolio/fund-transactions`: writes screenshot-derived order rows to transaction/fund tables. It is authenticated and undocumented. It accepts `{ rows: Array<object> }` and silently skips invalid rows while returning inserted/skipped/missing-fund results.
- `POST /api/portfolio/funds`: creates or exposes personal fund holding data and is authenticated but undocumented.
- `GET /api/portfolio`: returns personal holdings, certificates, transactions, and portfolio settings. It is authenticated and documented.
- `PATCH /api/portfolio/funds/{key}`, `PATCH /api/portfolio/gold/settings`, `POST /api/portfolio/gold/transactions`, and `POST /api/portfolio/snapshots`: mutate or expose personal financial state. They are authenticated; only the latter three documented operations are currently represented in OpenAPI, while the fund-create route is not.
- `GET /api/portfolio/usd-rate`, `/eur-rate`, and `/gold-prices`: market-rate endpoints mounted behind auth even though the values are not personal balances; they are undocumented.
- AI-bot, verdict, advisor, and alert routes expose derived portfolio/holding analysis and should be included in the contract/security review.

## Undocumented Endpoint Shapes

The following are based on backend route handlers, not frontend assumptions.

### `GET /api/ai-bot/status`

- Request: no body. Optional internal persisted state; no required query.
- Success: status object containing `running`, `runId`, stage state, timestamps/error where available, `stage_counts`, `stage_errors`, and chart-reader failure information.
- Error behavior: falls back to in-memory status JSON if persisted status lookup fails.

### `POST /api/ai-bot/run`

- Request: empty body.
- Success: `202 { running: true, runId: number }`.
- Conflicts: `409 { error: string }` when the advisory lock is held.
- Failure: `503 { error: string }` when the lock/database is unavailable.

### `POST /api/advisor/generate-opportunities?runId={id}`

- Request: no body; required positive integer `runId` query.
- Success: `{ success: true, results: array, analysis_summary: string }`; if no entities, a successful empty result is returned.
- Conflicts: `409` if the run is not completed/partial or generation lock is held.
- Failure: `400` for missing run, `500` for generation failure.

### `GET /api/advisor/recommendations?runId={id}`

- Request: required positive integer `runId` query.
- Success: array of held-position recommendation rows containing `ticker`, `recommendation_text`, `model_used`, `generated_at`, `generation_status`, `error_message`, and nullable `structured` data. Structured data contains decision, confidence, summary, thesis risk, evidence, risks, next-review days, watch trigger, and do-not-act reasons.
- Failure: `400` missing/invalid run, `500` query failure.

### `GET /api/advisor/opportunities?runId={id}`

- Request: required positive integer `runId`; optional `force=true` can trigger deterministic recomputation.
- Success: deterministic opportunities analysis plus `persisted_opportunities` when not forced. The analysis includes strong unheld entities, held winners/laggards/opportunities, sector gaps/concentration, risk comparison, and summary fields.
- Failure: `400` missing run or no available bot run, `429` rate limit for forced refresh, `500` query/analysis failure.

### `GET /api/alerts/summary?runId={id}`

- Request: required positive integer `runId` query.
- Success: `{ generatedAt, alerts: Record<ticker, { timeStop?, thesis? }>, portfolio: { drawdown } }`.
- Failure: `400` missing/invalid run, `500` computation failure.

### `GET /api/portfolio-summary?runId={id}`

- Request: required positive integer `runId` query.
- Success: persisted summary with counts, value percentages, decision, confidence, evidence, risks, review days, model, and generated timestamp.
- Failure: `400` missing/invalid run, `404` if no summary exists, `500` query failure.

### `GET /api/portfolio/usd-rate`, `/api/portfolio/eur-rate`

- Request: no body/query.
- Success when cache exists: the corresponding rate cache object, including rate/status metadata.
- Success when unavailable: `{ status: "unavailable" }`.

### `GET /api/portfolio/gold-prices`

- Request: no body/query.
- Success when cache exists: gold price fields plus `globalGoldUsdPerOz` and `globalGoldStatus`.
- Unavailable success: status object with nullable global gold values.

### `POST /api/portfolio/funds`

- Request body: `{ key, ticker, name, icon?, unitsHeld, costBasisTotal, nav }`.
- Backend requirements: normalized key matching `[a-z0-9][a-z0-9_-]{0,39}`, nonempty ticker/name, finite nonnegative units/cost, and positive finite NAV.
- Success: `201` created fund object.
- Conflicts: `409 { error, fund }` if key exists. Invalid input: `400`.

### `POST /api/portfolio/scan`

- Request body: `{ image: string, mimeType: string, mode: string }`; image is base64 without the data-URL prefix as sent by the frontend.
- Required: image, MIME type, mode, and configured server AI key. Authentication comes from router-level `requireAuth`.
- Provider behavior: Qwen is preferred when configured; Gemini fallback models are attempted; OpenRouter may be used for JSON parse fallback.
- `orders-list` success: `{ rows: Array<{ assetType, fund?, side, pricePerUnit, amountEgp, occurredAt? }> }`.
- Other modes success: `{ fund: string | object, nav?: number, unitsHeld?: number }`.
- Errors: `400` missing required fields/key, provider status with friendly error when models fail, `422` for empty/unparseable/invalid AI output.

### `POST /api/portfolio/fund-transactions`

- Request body: `{ rows: Array<object> }`; each row may include `fund`, `assetType`/`asset`/`ticker`, `side`/`txType`/`type`, `pricePerUnit`/`price`, `amountEgp`/`amount`, and optional `occurredAt`.
- Invalid rows are skipped. Valid buys can create missing fund rows; sells for missing funds are recorded in the missing-funds result.
- Success: `{ inserted: Transaction[], skippedDuplicates: Array<{ asset, amount, occurredAt, reason }>, missingFunds: string[] }`.
- Empty/missing rows: `400 { error: "Missing rows array" }`.

### `PATCH /api/watchlist/{ticker}/portfolio-bucket`

- Request body: `{ portfolio_bucket: "safety" | "steady_growth" | "broad_market" | "individual_stocks" | null }`.
- Success: `{ id, ticker, portfolio_bucket }`.
- Invalid bucket/ticker: `400`; unknown ticker: `404`; database failure: `500`.

### `GET /api/scraper/snapshots`

- Query: optional numeric `runId`, optional `since` timestamp.
- Success: `{ snapshots: array, lastRunAt: string | null }`. Snapshot rows include watchlist identity, holding state/bucket, market returns, risk/signal, fundamentals fields, and fetch status.
- Failure: `500 { error }`.

### `GET /api/technical-signals`

- Query: optional numeric `runId`.
- Success: `{ signals: array }`; each row includes watchlist identity, candle date, trend, patterns, confidence, raw-fetch status, candles, and created timestamp.
- Failure: `500 { error }`.

### `GET /api/rotation-verdicts?runId={id}&all=true`

- Query: required positive numeric `runId`; optional `all=true` includes all non-reserve entities instead of held entities.
- Success: array of current production `HoldingVerdict` objects.
- Failure: `400` missing/invalid run, `500` judge failure.

## Follow-up Notes

- No frontend-called endpoint was found to be missing from the backend.
- The most important undocumented endpoint for the next security review is `POST /api/portfolio/scan` because it accepts personal screenshots and forwards them to external AI providers.
- The largest contract gap is the AI workflow surface: the frontend manually types response shapes in `AiBotWorkspace.tsx` while the backend owns the real response structures.
- This report intentionally does not modify OpenAPI or generated clients. Updating those contracts is a separate task.
